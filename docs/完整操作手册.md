# 双摄实验室安全监测系统操作手册

外置 USB 全景相机与 DroidCam Wi-Fi 台面相机比赛版

文档版本 1.1（公开文字版）　更新日期 2026 年 10 月 23 日

公开范围说明：本仓库只发布源码与手册文字，不包含模型、APK、演示样本、任何图片、字体或 Word/PDF 附件。下文介绍的是原笔记本已配置版本的完整功能；“本机”“自带样本”“安装包”指本地保留的资料，不代表这些文件可从公开仓库下载。新设备先按附录另行准备模型并在本地构建小屏。原笔记本无需因公开发布重新安装。

适用软件：电脑纯视觉比赛版与安卓小屏 2.1-droidcam-wifi。适用对象：首次接手项目的报告人、演示人员、值守人员和事件复核人员。

本手册按当前程序的真实按钮和处理逻辑编写。照着“快速开始”可以在已配置的笔记本上启动双摄；首次安装、重新配对、事件处理、比赛演示和维护方法见后续章节。当前全景使用外置 Web Camera，台面使用手机单个后置主摄，电脑负责识别与事件管理，手机负责拍摄台面并显示随身小屏。

## 快速开始

1. 将外置 Web Camera 插入电脑 USB；将手机固定在台面侧上方，后置主摄对准器皿区域。
2. 手机开启个人热点，电脑连接该热点。手机和电脑的状态、视频均经 Wi-Fi 传输。
3. 在项目根目录双击“启动双摄实拍.bat”，等待电脑主控窗口和模型加载完成。
4. 手机打开“实验台随身小屏”，点“连接 Wi-Fi 摄像头”。需要时会切到 DroidCam，接通后返回小屏。首次系统询问是否允许小屏打开 DroidCam 时，允许该协作。
5. 确认电脑左侧是外置相机全景、右侧是手机台面，手机显示“DroidCam 已连接”、实收帧率有读数且画面持续更新。手机 USB 数据线可以拔掉，外置相机 USB 保持连接。

若自动连接失败，手机点“启动 / 设置 DroidCam”，选择 Camera 0、1×后置主摄，等电脑收到画面后返回小屏。若显示电脑未连接，先按第四章重新配对。

日常使用保持手机热点、小屏亮屏和 DroidCam 后台运行。默认无需联网推理或单片机；首次下载安装依赖和 DroidCam 时可能需要互联网。

## 一 了解系统和适用范围

### 1 系统组成

| 部分 | 当前使用设备或程序 | 主要任务 |
|---|---|---|
| 电脑主控 | 本笔记本与本地 Python 环境 | 运行两个模型、汇总状态、记录事件、展示和复核截图 |
| 全景通道 | 外置 USB Web Camera | 拍摄人员和实验区，提供防护装备及行为识别画面 |
| 台面通道 | 安卓手机 DroidCam 单个后置主摄 | 通过 Wi-Fi 向电脑提供台面视频，供器皿识别和近边提示 |
| 手机小屏 | 实验台随身小屏 | 显示电脑计算的状态、两路画面、事件，执行抓拍等操作 |
| 连接网络 | 手机热点或同一局域网 | 电脑拉取手机视频，手机访问电脑状态与控制接口 |

当前不使用故障的笔记本 Integrated Camera，也不把手机虚拟摄像头当作全景。全景和台面应有独立视角。手机小屏与官方 DroidCam 是两个相互协作的应用；卸载 DroidCam 后，小屏不能独自采集台面相机。

### 2 当前提供的功能

- 人员与防护：护目镜、实验服、手套、口罩等模型支持类别；头罩违规可在事件中显示。提供实验区饮食、疑似伏案和人员在场提示。
- 台面：识别现有模型支持的器皿，显示当前检出数量；结合已标定桌边线提示器皿靠近边缘。
- 协同：电脑主控、网页主控与安卓小屏共享状态；实时画面和识别标注可切换。
- 留痕：自动事件、手动抓拍、双路截图、本地事件库、人工复核和图片导出。
- 手机操作：Wi-Fi 配对、DroidCam 启动、台面连接与停止、静音 60 秒、现场求助。

本版已移除温湿度、温度检测、烟雾、温度预测、继电器或供电控制、串口、单片机和开发板部署等功能。界面残留的“环境/行为异常”是一处综合状态文案，不表示存在环境传感器。系统提供视觉提示和本机记录，不会自动切断设备电源。

## 二 准备设备与摆放机位

### 1 启动前准备

本机环境和模型已经配置好，无需重复安装。准备笔记本电源、已验证的外置 USB 相机、安装官方 DroidCam 与小屏的安卓手机，以及固定手机的支架。首次自动配对另需可传数据的手机 USB 线，日常 Wi-Fi 使用可以拔掉此线。

本机主目录为“桌面 → 人工智能算法精英大赛 → lab-safety-monitor”。请从该目录启动，避免误打开旧项目文件夹。

### 2 摆放与独立来源检查

1. 外置相机朝向人员上半身与实验区，保证人员不被屏幕、椅背等遮挡；检查光照与清晰度。
2. 手机使用后置 Camera 0、1×主摄，固定在台面侧上方，覆盖器皿与真实桌边。不要切前摄、超广角或多摄模式。
3. 轻轻遮住外置相机镜头，电脑全景应单独变暗；移开后恢复。再短暂遮住手机主摄，只有台面应变暗。两个画面都不响应时，先核对当前是否处于样本回放。
4. 固定机位后按第十一章标定桌边线。默认参考线不能直接当作真实桌边。

请保持手机镜头方向和摆放角度稳定。画面旋转不合适时，先调整手机朝向与支架，不要在比赛中频繁切换摄像头。

## 三 首次安装与自动配对

### 1 手机安装准备

本机手机已安装小屏与官方 DroidCam，可直接跳到第四章或快速开始。更换手机时，先安装官方 DroidCam，再安装项目的“android/LabGuard-Pocket.apk”。小屏支持 Android 8.0 及以上，安装包使用本地签名。

官方 DroidCam 需要相机权限；通知权限有助于其后台运行。当前只传输视频，不启用音频。小屏自身不申请或打开相机，仅通过网络与 DroidCam 协作。

realme 可能询问“小屏想要打开 DroidCam”，请允许该协作。DroidCam 设置中的“Power and Screen → Ignore Battery Optimizations”可用于减少其后台被省电机制限制；本机已对 DroidCam 开启该选项。

### 2 本机自动安装与配对

1. 手机开启个人热点，电脑先连接热点。
2. 电脑启动“启动双摄实拍.bat”，等待服务运行。
3. 手机用数据线接电脑，开启开发者选项与 USB 调试，并在手机上允许此电脑调试。只保留一部用于演示的手机。
4. 在项目根目录双击“连接安卓手机.bat”。脚本安装或覆盖更新小屏，识别同网段电脑地址，写入配对信息并打开小屏。
5. 手机按提示允许安装及应用协作，然后点“连接 Wi-Fi 摄像头”。确认电脑已有台面画面，再拔掉手机 USB。

该脚本使用 USB 完成安装和配置，不建立 USB 视频或状态转发。日常相机共享和小屏通信走 Wi-Fi。若脚本提示未发现授权手机，检查线缆是否支持数据传输和手机授权弹窗；若提示服务未启动，先打开电脑主控窗口。

### 3 手动安装的替代方式

也可将 APK 传到手机后手动安装，再按第四章填写电脑地址和配对码。这种方式不依赖电脑 Android SDK 或 USB 调试；本机自动脚本所需的兼容 ADB 已随本机环境准备好。请保留同一签名的 APK 更新，避免不必要的卸载和配对信息丢失。

## 四 网络地址和手动配对

### 1 推荐连接方式

推荐手机开启热点、电脑加入该热点。也可让两者加入同一个允许设备互相访问的局域网。仅看到两端都有 Wi-Fi 图标并不代表互通；访客网、校园网隔离和错误网段都可能阻止访问。

本次验收中电脑地址为 10.67.54.136、手机热点地址为 10.67.54.21。这些是当时的实例，不是固定配置。热点重开、换网络或换手机后应读取当前地址。

### 2 配对步骤

1. 电脑点“比赛演示 → 安卓小屏 Wi-Fi 配对信息”，或点主控中的“连接手机/副摄”。此操作会切到外置相机与手机实拍输入。
2. 记下与手机热点同网段的电脑地址、当前服务端口和配对码；若列出多个地址，避开 VPN、虚拟网卡等无关地址。
3. 手机点“配对 / 网络设置”，填写下表各项。
4. 点“保存并连接小屏 / DroidCam”。确认守护页面不再显示电脑未连接，再确认台面画面。

| 字段 | 填写方法 | 例子及限制 |
|---|---|---|
| 电脑地址 | 当前电脑局域网 IPv4 与服务端口 | http://10.67.54.136:8080；示例应替换为现场值 |
| 配对码 | 复制或输入电脑显示的完整配对码 | 大小写需一致，不要用热点密码代替 |
| 手机 IP | 通常留空，自动识别同网段接口 | 失败时填写手机热点 IP 或当前 DroidCam 可达地址 |
| DroidCam 端口 | 与官方应用内设置一致 | 默认 4747，允许范围 1024 至 65535 |

电脑地址只填基础地址，不加“/phone”或“?token=”。不要在手机填 127.0.0.1，它代表手机自己。当前只接受局域网 IPv4，不使用公网地址、域名或 IPv6。电脑服务通常为 8080；被占用时会尝试 8080 至 8099，应以电脑显示值为准。

手机同时连接普通 WLAN 并开启热点时，DroidCam 显示的 WLAN 地址可能与电脑所连热点不同。手机 IP 手动填写项应选择电脑可达的热点接口地址；小屏默认会尝试自动识别。

配对码保存在本机运行目录和手机应用私有设置中。不要将带配对码的链接、运行目录或设置截图发到公开仓库。更换网络后先重新配对，再检查视频，不要反复修改模型参数。

### 1 界面区域

本公开文字版不附界面截图，以下按电脑主控中的区域名称说明操作位置。

| 区域 | 查看或操作内容 |
|---|---|
| 顶部状态与提醒条 | 当前汇总状态、运行时间和待处理提示 |
| 左侧宏观行为 | 全景画面、人员状态和防护识别 |
| 中间微观台面 | 台面画面、器皿数量、近边标记与参考线 |
| 视觉状态栏 | 人员状态、手机连接情况和器皿数量 |
| 模型设置 | 模型开关、自定义模型、置信度、IoU、尺寸 |
| 推理模式 | 恢复实拍、连接手机或导入本地媒体 |
| 终端输出 | 当前识别类别、置信度、识别帧率和最近事件 |
| 右侧事件流 | 事件截图、正确或误报复核、抓拍与导出 |
| 底部状态栏 | 相机来源、Wi-Fi 实收帧率与模型识别帧率 |

窗口较小时可滚动查看下方控件。顶部“比赛演示”是本比赛版常用入口，优先通过该菜单切换实拍或样本。

### 2 比赛演示菜单

- “真实样本回放”：分别载入自带人员样本和器皿样本，用真实模型展示功能。
- “外置 USB 摄像头 + 安卓手机”：恢复两路实拍输入。
- “安卓小屏 Wi-Fi 配对信息”：显示电脑地址与配对码，同时选择实拍来源。
- “实时画面”：默认勾选，显示最新预览；取消勾选后查看识别标注。标注帧率受 CPU 推理速度限制。
- “打开网页主控屏”：在电脑浏览器打开同一服务的主控页面。
- “预览手机小屏”：在电脑浏览器查看小屏网页布局，不会把电脑变成手机摄像头。

主控里“单摄模式”是沿用的按钮名称，当前绑定的是恢复配置中的实拍来源。它不是将两路都改为手机。实际来源应以窗口标题、状态栏和遮挡测试为准。

## 六 安卓随身小屏

### 1 守护页面

“守护”显示人员在场状态、手机主摄实收帧率、器皿数量、四项防护状态和当前事件。识别结果来自电脑，手机本身不运行 YOLO。

四项防护显示“已观察到”“有违规”或“待确认”。“待确认”说明证据不足；不能把它当作合格。头罩、饮食和疑似伏案等其他类别可能出现在事件提示中，不一定有单独的状态方块。

### 2 画面页面

点“画面”查看全景和台面。选“实时画面 · 24 帧目标”用于观察动作和流畅度；选“识别标注”查看检测框、类别、置信度及桌边参考线。右侧固定区域是电脑返回的台面预览，与官方 DroidCam 使用同一主摄。

### 3 事件页面

点“事件”查看本次运行最近的事件、时间、截图和复核结果。手机页面用于查看，复核操作在电脑原生卡片或网页主控中完成。页面只展示最近一部分记录，并非全部历史事件档案。

### 4 右侧连接按钮

| 按钮 | 使用时机与结果 |
|---|---|
| 启动 / 设置 DroidCam | 手动打开官方应用，选择主摄或修改官方设置；完成后返回小屏 |
| 连接 Wi-Fi 摄像头 | 提交手机地址并选择电脑实拍来源；需要时唤醒 DroidCam，接通后切回小屏 |
| 停止台面传输 | 停止电脑台面接收并使该通道旧帧失效；外置全景继续运行 |
| 配对 / 网络设置 | 修改电脑地址、配对码、手机 IP 和 DroidCam 端口 |

断线恢复有连接与重试过程，可能短暂显示 DroidCam 窗口。等待恢复；若手机系统拦截自动切回，按返回键回小屏。短时间连续点击不会使网络恢复更快。切出后再返回小屏会尝试重新连接台面；要结束演示，应按第十二章退出整个流程。

### 5 底部操作按钮

“抓拍”在电脑创建一次手动事件和双路截图，不是把照片存入手机相册。“静音 60 秒”更新提示音静音时限，视觉提示与事件记录继续；浏览器声音、振动还取决于系统权限和是否已有用户交互。再次点静音会重新计算 60 秒。

“现场求助”在电脑主控留下求助事件与截图，不会发送短信、电话、邮件或通知远程管理员。点后应从电脑事件流确认记录已产生，需要他人帮助时仍应现场联系。

## 七 理解识别结果和提醒

### 1 汇总状态

| 状态 | 当前含义 | 建议操作 |
|---|---|---|
| 正常守护 | 当前没有需要汇总为提醒或警告的活动事件 | 继续观察，并结合防护状态判断证据是否充分 |
| 请关注 | 存在一般提醒，例如防护或台面近边提示 | 查看事件内容、核实画面并纠正现场问题 |
| 需要处理 | 存在较高等级活动事件，例如实验区饮食或全景中断 | 优先检查相关问题，必要时暂停演示和恢复来源 |
| 连接已断开 | 小屏无法读取电脑状态 | 检查电脑程序、热点、地址与配对信息 |

电脑原生界面可能显示 SAFE、NOTICE、WARNING 等英文徽标及略有不同的中文文案。当前汇总逻辑主要使用正常、提醒、警告三个等级。不要把未使用的界面样式当作已启用的硬件紧急处置。

### 2 人员防护和行为

人员模型识别出明确违规类别后，要经过时间投票才确认，单帧检出通常不会立即形成稳定事件。默认时间窗为 3 秒，确认比例 0.6，解除比例 0.2，最少 4 帧。此机制降低抖动，但不代表任何违规必在固定 3 秒内出现。

人员在场依据画面中的装备等证据保持状态。默认持续约 15 秒没有人员证据才转为无人，恢复需约 1 秒连续证据。因此短暂离开画面时“人员在岗”可能保持一段时间；它不提供身份识别或精确人数统计。当前无人提示属于信息级，不保证产生警告卡片。

疑似伏案采用头部位置、持续时间和运动程度的启发式提示，默认持续门槛为 10 秒。它不能确认一个人真的睡着。实验区饮食、防护违规和头罩提示也受模型能力、遮挡及画面质量影响，需人工核实。

### 3 器皿和桌边提示

器皿数量是当前帧模型检出的目标数量，不是经过盘点校验的库存。靠近参考桌边时可显示 EDGE 标记，并在时间投票后形成“器皿靠近台面边缘”事件。系统没有测量真实物理距离，也不保证预知跌落。

### 4 断线与画面无效

手机旧帧最长按默认 2.5 秒时效使用，过期后停止台面判断并显示离线，程序尝试重连。手动停止则立即使手机缓存失效。全景读不到真实帧时显示全景未接入，不会自动用手机画面补位，也不应把设备故障解释为人员离岗。

### 5 视频帧率和识别帧率

Wi-Fi“实收”统计电脑收到的唯一新帧，目标 24 FPS；YOLO“视觉”帧率反映模型处理速度，两者独立。CPU 识别数 FPS 时，实时预览仍可接近 24 FPS。识别标注可能比动作稍晚，属于推理耗时，不能因此把标注帧率当作网络上传帧率。

2026 年 10 月 22 日，本机在手机 USB 拔掉后连续 30.67 秒平均实收 23.996 FPS。这是当时测试结果，不是所有光照、网络和设备条件下的固定保证。

## 八 抓拍复核与图片导出

### 1 抓拍与自动事件

电脑右侧“抓拍”和手机“抓拍”都会形成手动记录。自动识别确认事件时，系统也会生成相应事件。卡片包含时间、事件名称、说明和双路缩略图。截图通常保存最近一次识别标注画面，可能略早于最新实时预览。

连续存在的同类问题不会每帧新建卡片；短时间解除又出现时也可能合并为原事件。活动提醒解除后，原事件仍可留在记录中。部分连接状态事件没有独立截图；界面卡片可能显示当时可取得的画面作为查看参考。

### 2 人工复核步骤

1. 在电脑右侧选择要核验的卡片，点卡片空白位置可打开“大图评审与导出”。
2. 对照事件说明与双路画面，判断当时的提示是否成立。
3. 点“正确”或“误报”。大图窗口也可用“正确（计分）”或“误报（不计分）”。
4. 查看卡片颜色、待评审数量和复核汇总是否更新；手机“事件”会同步显示结果。
5. 在大图窗口用“上一张”“下一张”继续核验其他事件。

当前界面每条记录仅支持一次复核，按钮操作后禁用；没有撤销复核入口。复核结果只给事件加人工标签，不会自动清除活动告警或训练模型。误判时应保留说明并交由维护人员处理，不要通过删除事件库来重做。

### 3 准确率与总分的口径

界面“准确率”按已复核记录中“正确”的比例计算，例如 8 条已复核中 6 条正确，显示约 75%。尚未复核的记录不计入该比例。它不是独立测试集上的模型准确率、召回率或 mAP。

每条复核为正确的记录使当前界面演示分增加 1.75，最高 35；误报不加分。手动抓拍也可以复核，因此这个分数只能说明本次界面的复核计分，不是官方比赛评分或安全等级。重启后的界面统计不保证延续本次会话。

### 4 导出图片

单张导出：点卡片进入大图窗口，点“导出单张”，选择文件夹、文件名和 PNG/JPG/JPEG 格式，保存后打开文件确认。导出的是左右拼接的双路截图；某一路当时无有效画面时应结合事件说明查看。

批量导出：点电脑右下“导出”，选择目标文件夹。程序导出当前会话已收集记录的合并图片，并提示导出数量。文件名包含序号、时间和事件类型。建议每次演示使用新文件夹，避免与旧场次混淆。

当前导出功能不生成 Excel、PDF 事件报告或完整录像，也不提供录像录制按钮。自动落盘的原始事件截图与界面导出的图片可能有不同尺寸，两者均可按需备份。

## 九 样本回放和本地媒体

### 1 自带样本

双击“启动比赛版.bat”默认进入自带样本回放；也可在电脑菜单选择“真实样本回放”。该模式分别加载人员样本和器皿样本，运行真实模型，用于讲解界面与判断流程。

样本展示期间不要在手机再次点“连接 Wi-Fi 摄像头”、进入配对信息或切回触发重连，这些动作会把电脑切回实拍。需要只预览小屏布局时，可用电脑“比赛演示 → 预览手机小屏”。已连接的小屏保持前台时，可以查看电脑随后切换到的样本结果。

### 2 导入图片或视频

1. 点电脑“导入媒体”。
2. 选择 MP4、AVI、MOV、MKV 视频，或 JPG、PNG、JPEG 图片。
3. 查看媒体名称、模型结果和终端输出；视频出现播放进度控件。
4. 对视频可用暂停或继续按钮，拖动进度条后松开以跳转。图片为静态画面。
5. 演示完成，从菜单“外置 USB 摄像头 + 安卓手机”恢复真实双摄。

当前导入入口选择的是单个文件，该文件会同时送入两侧模型。因此导入后两侧出现同一场景属于该功能的现有行为，不能据此判断实际双摄接错。当前没有分别选择两个文件的用户界面。

样本与视频回放用于展示功能；演示时应明确说明“当前是回放”，不把它描述为手机现场拍摄或独立准确率测试。

## 十 模型开关与参数调整

### 1 两个模型开关

“人员模型”控制全景识别，“物品模型”控制台面器皿识别。按钮选中表示启用，取消表示停用相应模型。比赛前通常保持两者启用。关闭模型会暂停相应判断，不能将没有检出结果解释为现场已合格。

### 2 调整推理参数

| 参数 | 本机默认值 | 调整影响 |
|---|---|---|
| 置信度 | 0.35 | 提高会过滤更多低置信目标；降低可能增加检出和误报 |
| IoU | 0.45 | 控制重叠框过滤，需要结合重复框情况调整 |
| 尺寸 | 416 | 较大输入可能有利于小目标，同时增加 CPU 耗时 |

操作时先记下原值，只改一项，再点“确认修改”，观察同一场景下结果。CPU 演示不宜为了检测框更密集就持续增大尺寸。输入尺寸按 32 的倍数使用；本机当前建议先保留 416。

界面修改通常用于当前运行会话，不应假定已永久写入 config.yaml。若重启后需继续采用新值，由维护人员修改配置并再次核验。运行目录中的配置覆盖项也可能优先于基础配置。

### 3 自定义模型

点“自定义...”，选择可信 .pt 模型，指定“人员模型（全景 Camera A）”或“物品模型（台面 Camera B）”，等待成功或失败提示。选择的模型类别和语义必须兼容本系统，不能把任意检测模型当作防护或器皿模型。

该入口是模型加载，不是训练界面，也不意味着自动复制模型到项目目录或永久替换默认路径。报告前使用已验证的 ppe_best.pt 与 chem_best.pt；若要恢复默认模型，可重新选择原文件或重启程序后核对。

## 十一 标定桌边和更换设备

### 1 桌边标定

当前没有图形化画线工具。固定手机后，在识别标注画面中找到真实桌边的两个端点，由维护人员修改“labguard/config.yaml”里的 desk.edge_line；每个坐标按图像宽高归一化到 0 至 1。

例如宽 640、高 480 的图像中，若桌边确实是 y=400 的水平线，端点可写为 [[0.0, 0.833], [1.0, 0.833]]。这只是坐标换算示例，应使用现场真实位置。默认 [[0.0, 0.92], [1.0, 0.92]] 是初始参考。

修改前备份配置，退出主控后编辑并保存，再重新启动、切到识别标注，确认参考线与桌边重合。把空器皿放在内侧与近边区域验证提示。desk.edge_margin 默认 0.06，是图像归一化距离阈值，不是 6 厘米；改变机位、画幅或手机方向后要重新检查。

### 2 更换外置相机

全景按精确名称“Web Camera”选择。更换为其他型号时，先确认 Windows 中的实际设备名，再修改 camera.pano_name。找不到唯一设备时程序会显示离线，不会扫描切换成手机或故障内置相机。同名多设备同时接入也可能导致选择失败。

### 3 更换手机或端口

更换手机后重新安装 DroidCam 和小屏，授权并配对。修改 DroidCam 官方端口时，同步修改小屏配对页的端口。只在一处修改会导致电脑状态页面可访问、台面却连不上。

不要在手机关闭热点后仍使用旧地址，也不要为解决问题关闭系统防火墙。电脑只需允许本项目 Python 在所用局域网配置下的入站访问。

## 十二 结束演示与数据保存

1. 停止新的演示动作，等待最后一条需要保留的截图出现在事件中。
2. 完成必要复核，导出需要的图片；打开至少一张导出图确认保存成功。
3. 关闭电脑主控窗口，停止本次识别和小屏服务。
4. 手机退出小屏，再在 DroidCam 中停止相机；最后关闭热点。外置相机不再需要时可拔掉。

程序运行中不要拔掉外置相机或删除事件库、配对文件。手机 USB 数据线日常可拔，手机需要充电时可连接充电器；这不改变 Wi-Fi 视频来源。

### 数据位置与保留方式

| 位置 | 内容及处理方法 |
|---|---|
| labguard/runtime/events.db | 本地事件与复核数据；关闭程序后连同运行目录备份 |
| labguard/runtime/snapshots/ | 按日期分类的自动事件合并截图 |
| 手工选择的导出文件夹 | 单张或批量导出的图片，由操作人指定 |
| labguard/runtime/ 中的运行日志 | 启动、错误和故障定位记录；发生异常时保留对应时间段 |
| labguard/runtime/config_override.yaml | 本机运行覆盖设置，例如 DroidCam 地址和启用状态 |
| labguard/runtime/web_token.txt | 本机配对码，不公开共享 |

当前事件网页读取最近会话内存中的记录，最近事件接口最多返回 60 条；界面没有完整历史库浏览、按日期检索、删除或自动回载旧记录的入口。数据库有落盘记录不代表重启后卡片和分数会自动恢复。重要截图应在退出前主动导出。

本机离线备份应包含整个项目及“.runtime”环境、模型和运行数据。本公开 GitHub 仓库仅保留源码与文字文档，排除模型、APK、演示样本、图片、字体、Word/PDF 附件，以及“.runtime”、日志、事件库、配对信息和现场截图；仅下载源码不会得到本机已配置的完整环境与资料。

## 十三 比赛演示推荐流程

### 演示前核对

- 外置相机独立来源检查通过，手机仅使用后置主摄。
- 电脑加入手机热点，小屏状态与两路画面可正常刷新。
- “人员模型”“物品模型”都开启，默认参数已记录。
- 手机机位固定，桌边线已经检查；使用空器皿和可控场景演示。
- 准备好图片导出文件夹；已区分样本回放和实拍入口。

### 约五分钟的操作顺序

1. 用简短说明介绍两个视角：全景看人员与行为，台面看器皿，电脑统一识别，手机兼作小屏。
2. 可先切“真实样本回放”，展示模型标注；明确样本来自已有项目资料。
3. 切回“外置 USB 摄像头 + 安卓手机”，移动手部或空器皿，让评委确认两路实拍来源独立。手机 USB 可拔掉证明 Wi-Fi 传输。
4. 手机“守护”展示防护状态与事件，再进入“画面”切换实时和识别标注，说明两个帧率的不同。
5. 手机点“抓拍”，电脑打开事件大图、人工复核，再从手机“事件”查看同步结果。
6. 导出一张图片作为留痕。如需演示故障恢复，短暂停止台面并恢复，说明全景仍独立运行。

若现场网络暂时中断，先说明当前状态不可判断，再恢复连接；恢复耗时较长时可切样本回放继续讲解。不要把回放画面冒充已恢复的实拍视频。

## 十四 常见问题与处理顺序

遇到问题按“电脑是否运行 → 网络与配对 → 摄像头 → 模型与显示”的顺序检查，避免同时改多项设置。

| 现象 | 优先检查 | 处理方法 |
|---|---|---|
| 双击启动后没有新窗口 | 程序是否已经运行 | 先从任务栏切回比赛窗口，程序有单实例限制 |
| 提示独立环境缺失 | 是否只是从 GitHub 下载了源码 | 本机应使用原完整目录；新电脑按附录安装环境 |
| 手机显示电脑未连接 | 主控是否运行、热点及电脑地址 | 重启主控后核对当前地址与端口，重新配对 |
| 配对信息无效 | 配对码是否完整且一致 | 从电脑配对信息重新填写，不使用热点密码 |
| 有状态但台面黑屏 | DroidCam 是否启动，手机 IP/端口 | 点连接，必要时手动启动 DroidCam 后返回；手机解锁 |
| DroidCam 显示 Busy 或占用 | 是否有其他客户端同时拉流 | 关闭其他 DroidCam 客户端、播放器或直接访问视频接口的网页，仅保留本项目拉流 |
| 拔手机 USB 后离线 | 是否仍在依赖旧配置，网络是否同网段 | 使用 Wi-Fi 版小屏重新配对，确认电脑连接手机热点 |
| 全景未接入 | 外置 USB、设备名、独占占用 | 检查相机连接，关闭其他占用程序，核对 Web Camera 名称 |
| 两侧画面完全相同 | 是否处于导入单文件回放 | 先切实拍，再做分别遮挡镜头测试 |
| 实时画面出现回跳 | 是否运行旧代码或重复实例 | 关闭旧窗口，从当前目录重新启动；不要继续使用旧 USB 原型 |
| 画面流畅但标注慢 | 是否查看 CPU 识别帧率 | 切回实时画面；保留 416 尺寸，减少其他重负载程序 |
| “待确认”一直存在 | 光线、遮挡、目标大小和模型类别 | 改善机位与画面，勿将证据不足当作防护合格 |
| 移动物品后未立即告警 | 时间投票和真实桌边标定 | 保持可见并等待确认，核对桌边线与阈值 |
| 点抓拍没有卡片 | 模型是否已有可用结果 | 等待首批识别画面，回电脑查看事件；关闭或断线状态不保证有效截图 |
| 点正确或误报无反应 | 是否已经复核过 | 已复核按钮会禁用；当前没有撤销入口 |
| 求助后没有远程通知 | 当前功能是本机记录 | 从电脑查看“现场求助”事件，并现场联系人员 |
| 手机息屏后视频中断 | 锁屏或 DroidCam 后台限制 | 解锁、保持小屏亮屏，打开 DroidCam 后返回并检查后台设置 |
| 重启后卡片或分数消失 | 这是新运行会话 | 从已导出图片或本机备份查找记录，不把卡片消失等同数据库已删除 |
| 导出时提示无数据 | 当前会话没有抓拍记录 | 先抓拍形成事件，再导出 |

故障仍无法排除时，记录出现时间、当前模式、两路是否有效、实收与识别帧率，以及最近错误日志。不要直接运行旧的内置相机驱动调试脚本；当前方案依赖外置相机。

py -3.11 -m venv labguard\.venv
labguard\.venv\Scripts\python.exe -m pip install --upgrade pip
labguard\.venv\Scripts\python.exe -m pip install `

# 版本依据

- 上游：[SSSSSmilewei/lab-safety-monitor](https://github.com/SSSSSmilewei/lab-safety-monitor)
- 分支：`main`，获取时最新提交 `83aa8eada7800679f60571e5085a4be57e1e9444`，2026-10-19。
- 本地改造分支：`competition/android-vision`。
- 改造直接应用于新克隆的上游代码，未以先前桌面文件夹作为程序基础。原笔记本演示用样本从旧资料复制到本机 `labguard/media`，不会依赖原文件夹运行；公开仓库只发布源码和文字，模型、APK、样本及图片均不上传，也不携带包含这些资料的原 Git 历史。

## 本地旧原型与 GitHub 新版的关键区别

| 项目 | 本地旧原型 | GitHub 新版与本比赛版 |
|---|---|---|
| 核心逻辑 | 主要由窗口驱动状态评估 | 独立引擎统一提供快照，界面不承担判定 |
| 人员在场 | 只识别部分口罩、头部类别为人员 | 任意人员装备证据都可代表有人；默认连续 15 秒无证据才认为无人 |
| 画面无效 | 可能继续得出无人判断 | 画面无效暂停该通道判断，不把断线当无人 |
| 违规告警 | 单帧容易触发 | 3 秒时间窗投票，有确认与解除滞回 |
| 台面边缘 | 使用固定像素区域 | 使用归一化桌边线和距离，可适配分辨率 |
| 帧队列 | 有积压导致延迟的风险 | 队列丢旧保新，优先处理最新画面 |
| 事件 | 以手动抓拍和界面卡片为主 | 违规自动事件、防抖、SQLite、截图、专家复核写回 |
| 界面性能 | 大量阴影效果 | 沿用上游自绘卡片、局部海浪刷新与状态变化更新 |

## 比赛版保留、移除和新增

保留两个上游 `.pt` 权重、YOLO11 识别、人员在场、装备违规、饮食、疑似伏案、器皿种类和近桌边提示、事件卡片、抓拍、导出与复核，以及原有水蓝/靛蓝像素界面风格。

移除上游温湿度、热源温度、烟雾、温度预测、环境调节、供电控制、串口、固件、开发板部署和硬件专用模型。比赛版界面与接口中不保留这些功能。原完整系统文档和 PPT 也从此比赛分支移除，历史仍保存在 Git 上游提交中。

为使比赛版无需额外服务、账号或大模型下载，同时移除可选大模型安全助手和 V‑JEPA 扩展。它们仍可从原仓库获取；本版专注视觉识别与手机协同。

新增安卓小屏：守护/画面/事件三页、双路抓拍、提示静音、现场求助。2026-10-22 将手机 USB 上传替换为 DroidCam Wi-Fi；小屏不再打开 Camera API，官方 DroidCam 单个 Camera 0 主摄负责采集，电脑通过热点 IP 直连官方 MJPEG 接口。外置 USB Web Camera 独立负责全景，故障内置相机不再参与。

小屏集成配对、官方 DroidCam 启动、Wi-Fi 接入/停止、实收帧率和断线唤醒。首次系统可能确认小屏能否打开 DroidCam，允许该协作后，连接恢复会短暂切到 DroidCam，再返回小屏。电脑监听局域网端口，状态与控制接口需配对码。USB 仅用于首次安装及自动配对；项目旧转发和上传接口已移除。

新增手机帧会话隔离、递增序号、尺寸上限、过期丢弃和断线显示。手机断线后不再拿旧帧充当实时输入。已观察到的装备与“未检测到违规”分开处理，证据不足显示“待确认”。

## 验证口径

`test_backend.py` 检查视觉防抖、人员在场、事件、手机帧轮转/断线/乱序/会话；`test_platform.py` 检查局域网鉴权、地址约束、接入/停止、页面、字体、复核与已移除接口；`test_droidcam.py` 检查 MJPEG 分帧、24 FPS 节奏、断线失效及重连。原生界面回归额外检查“延迟识别帧不能覆盖实时预览”，避免画面回跳。真机记录另存 `labguard/runtime/`。

疑似伏案是基于画面几何与持续时间的提示，不是人体疾病诊断；器皿近边提示需要按手机机位校准桌边线。样本回放用于演示功能，不能据此声称独立测试集准确率。
